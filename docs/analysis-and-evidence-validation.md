# Phases 11–13 — AI analysis, evidence validation, and service integration

## Workflow and boundaries

An authorized caller requests an analysis with `POST /api/v1/incidents/:incidentId/analysis` and reads the latest or a selected stored run with `GET /api/v1/incidents/:incidentId/analysis?analysisRunId=...`. The POST body is an empty object; the caller cannot select arbitrary alerts or evidence. Write and read scopes are enforced by Express. Missing incidents return 404, incidents without alerts return 409, an unavailable internal service returns 503, and malformed or invalid internal results return 502. The public API never exposes Python stack traces, provider errors, payload contents, or credentials.

Express loads the persisted incident, linked alerts, and relationships whose endpoints both belong to that incident. The bounded `v1` request passes only those records to the private authenticated FastAPI service. FastAPI does not connect to PostgreSQL. Express owns authorization, validation, and all authoritative writes. Analysis run, source-alert links, run evidence, findings, and audit event are written in one Prisma transaction. Failure and invalid-output audit events are written separately with a safe failure classification; no completed run is stored for those failures.

## Contracts and validation outcomes

The shared TypeScript schemas and matching Pydantic models live in `packages/shared/src/index.ts` and `services/ai/src/cybernexus_ai/contracts.py`. A shared JSON fixture is consumed by TypeScript and Python tests. The contract bounds alerts, relationships, findings, text, evidence references, and field paths; unknown keys are rejected. `analysisMethod` is `deterministic_fallback` or `gemini`.

Express independently checks each result reference against the exact incident request snapshot. The reference kind and identifier must match a supplied source alert or relationship, and every cited field path must be an allowed path for that record. Unknown, fabricated, wrong-incident, and unprovided-field references reject the whole response. A finding without references is retained only as `insufficient_evidence`. Validation statuses `references_validated`, `insufficient_evidence`, and `reported_conflicts` describe structural reference checks and reported ambiguity. They do not certify claim truth. The API sets `semanticVerification: "not_performed"`, forces human review, and persists every finding with `verificationStatus: "unverified"`.

The fallback reports source-record severity counts and persisted relationship state. Its `analysisConfidence` and finding `confidence` are ratios of distinct cited source records to available source records; they measure reference coverage only. They are neither probabilities nor judgments that a claim is supported. Relationships with `review_required` state are described as unresolved ambiguity, not confirmed contradictory evidence. Missing context, uncertainty, abstention, recommended review steps, and human-review rationale remain visible.

## Gemini adapter and fail-safe behavior

`services/ai/src/cybernexus_ai/providers.py` defines the provider interface and the Gemini adapter using Google's official `google-genai` SDK. The project requires Python 3.11; the SDK supports Python 3.10+ and its Pydantic 2.12.5 floor fits the project's Pydantic 2 range. The SDK is imported lazily, and tests inject a mocked client. No dependency installation or live Gemini request was performed during this task. Google's official docs recommend `google-genai` and support Pydantic response schemas ([SDK guidance](https://ai.google.dev/gemini-api/docs/libraries), [SDK source](https://github.com/googleapis/python-genai)).

The default remains `AI_PROVIDER=deterministic`; `GEMINI_LIVE_ENABLED=false` is an additional explicit outbound-call gate. A live adapter is selected only when `AI_PROVIDER=gemini`, the key and model are valid, and the live-call gate is explicitly true. Provide these variables only to FastAPI (for local development, use the ignored `services/ai/.env` loaded by Uvicorn); Express does not pass its environment to Python. `GEMINI_API_KEY` is passed only into the server-side SDK client. It is never returned or logged. Calls are bounded to 2.5 seconds, with no tools or action callbacks. Missing configuration, timeout, malformed output, rate limit, any provider error, or invalid evidence returns the existing `deterministic_fallback` result without exposing provider errors.

Gemini output is validated against the existing Pydantic response schema, request ID, required human-review state, uncertainty and `unverified` status. The Python adapter checks every alert/relationship ID and field path; Express independently repeats incident-snapshot evidence validation before persistence. Confidence values remain reference-coverage ratios, and proposed severity is derived by trusted code from source-reported alert severity. The model cannot authorize, prioritize, assign, persist, or execute actions. `analysisMethod: "gemini"` identifies provider-generated advisory text; it does not mean the claim was verified.

Only the bounded incident snapshot is sent: alert metadata and stored candidate relationship metadata. Raw payloads, logs, credentials, and unrelated incidents are absent from the request contract. Titles and relationship text remain untrusted and are explicitly framed as data, not instructions. Synthetic fixtures and mocks are used for testing. This task made no live request and sent no incident data to Google.

Before any live call, the owner must verify intended account and application eligibility, available region, and approved data-handling terms. Google's current [Gemini API Additional Terms](https://ai.google.dev/gemini-api/terms) require API users to be at least 18 and prohibit use in applications directed to or likely accessed by under-18s. For unpaid services, submitted content may be used to improve Google products and may be reviewed by humans; the terms say not to submit sensitive, confidential, or personal information. The app's eligibility and data policy have not been verified here, so live calls remain disabled.

## Untrusted content and analysis limitations

Alert titles are carried as untrusted data in the private request; the deterministic fallback does not use them. Raw provider payloads, credentials, unrelated incidents, and action tools are not sent to the fallback. Tests include instruction-like alert content, verify that the deterministic output is invariant to the title, and reject fabricated evidence references. The fallback cannot execute commands or take response actions.

The deterministic fallback remains the default and must not be described as live AI output. Gemini has not been live-tested, provider eligibility has not been cleared, and no model output has been evaluated against semantic evidence truth. The fallback is not a substitute for semantic evidence verification. Neither the fallback nor Gemini adjudicates source accuracy or causality; the adapter keeps proposed severity derived from source values, and Phase 14 policy code remains authoritative for risk scoring.

## Persistence and verification

The additive Prisma migration is `apps/api/prisma/migrations/20261029180000_incident_analysis/migration.sql`. It persists the analysis summary, proposed severity, coverage confidence, validation state, method/provider identity, human-review rationale, reported conflicts, source snapshot hash, evidence field paths, and per-finding validation status. The test database was verified as local PostgreSQL `cybernexus_test`; its migration status was up to date after deployment. The database integration suite is `apps/api/src/analysis/database.integration.test.ts` and exercises persistence/retrieval, source and relationship evidence, audit records, missing/empty incidents, unavailable service, and invalid evidence output. It skips when `CYBERNEXUS_TEST_DATABASE_URL` is absent and rejects any other host or database name.

Run the adapter and investigation tests with `python -m pytest -q services/ai/tests/test_investigation.py`; the full analysis service suite is `python -m pytest -q services/ai/tests`. API evidence validation tests run with `pnpm --filter @cybernexus/api exec vitest run src/analysis/evidence-validation.test.ts`. These tests use mocked SDK clients and synthetic fixtures only. For the Phase 11 adapter task, the full Python suite passed (32 tests), API evidence validation passed (7 tests), `pnpm test` passed (91 tests) with 11 database integration tests skipped, and typecheck, lint, format, build, environment, and diff checks passed. No live Gemini call was made and no migration ran. To run database tests, supply `CYBERNEXUS_TEST_DATABASE_URL` in the process environment, first verify the connection's database identity and loopback address, and check Prisma migration status. Never point tests at `cybernexus_dev`, apply migrations there, or print database URLs or credentials.
